# Lookup tables (F-LKP, decisions D-LKP-01..11)

Ground truth: `Modules/Core/database/seeders/data/workbook/v1_3/` (generated by
`/Users/ramadan/Umrany/implementation-plan/.tools/workbook/wb_export.py`; a hook blocks hand edits).
`registry.json` = every table to build: `code, group (master|master_tree|system|config|status|cr), shape (list|tree|setting_keys|cr|status), table, model, sheet, value_count_sheet, open_decision_refs`.
Design + shapes: implementation-plan `features/F-LKP-lookups-schema-baseline.md` §2–§3 and `01-architecture.md` §ARCH-LOOKUP.

## Rules (decided — don't re-ask)
- One table per lookup, `lkp_` prefix, `Modules/Core`; models `Modules\Core\Models\Lookups\<Model>`; system/status enums `Modules\Core\Enums\Lookups\<Model>` (value = exact workbook code).
- Columns come from the `lookupColumns('<shape>')` Blueprint macro; never re-declare them per table.
- `code` immutable, partial unique `WHERE deleted_at IS NULL`; explicit short index names (`<table>_code_uq`).
- Every seeded row: `wb_sheet`, `wb_row`, `value_source` (SRS|Proposed|CR), `is_active` exactly as the workbook.
- Values the workbook/SRS leave open → `value=null`, `value_status='open'`, `open_decision_code`. **Never type a default**; the only allowed non-null values are those written in the workbook (incl. sheet "Fixed Defaults").
- CR tables: seeded `is_active=false`, `cr_status='not_approved'`; business tables must not FK them.
- Business tables reference **code** (string FK + enum cast) for system/status/config, **id** (`restrictOnDelete`) for admin master data.
- Migrations: until the first staging deploy edit the baseline in place (LKP.1); after it, additive only (D-LKP-10). Check `docs/decisions/` ADR for the cut-over date.

## Workflow for a group/table
1. `jq '.tables[] | select(.group=="<group>")' Modules/Core/database/seeders/data/workbook/v1_3/registry.json` — confirm names/counts.
2. Scaffold (once the command exists — LKP.0.S1.T4): `docker compose exec app php artisan core:lookups:scaffold --group=<group>`; review the generated migration/models/enums; never hand-add values to enums.
3. Seed: `docker compose exec app php artisan db:seed --class='Modules\Core\Database\Seeders\WorkbookSeeder'`.
4. **Verify loop (max 5 rounds):** `docker compose exec app php artisan core:lookups:verify --group=<group>` → fix the *generator/seeder/migration* (never the JSON) → re-run until `0 mismatches`. Still failing after 5 → stop and report the diff to the user.
5. Independent audit: run the `workbook-auditor` agent with the group; resolve its findings the same way.
6. `migrate:fresh --seed` twice + `migrate:rollback` once (repeatability, AC4); `composer analyse`.
7. Plan sync (plan-sync agent) with the LKP ids.

## Using a lookup from a feature card
- Find it: `jq '.tables[] | select(.code=="TASK_PRIORITY")' .../registry.json`.
- Enum + FK by code: `$table->string('priority', 40); $table->foreign('priority', '<t>_priority_fk')->references('code')->on('lkp_task_priorities');` + `protected $casts = ['priority' => TaskPriority::class];`
- Validation: `Rule::exists('lkp_task_priorities', 'code')->where('is_active', true)` (active only for new input; history may hold inactive codes).
- Settings: `Settings::require('<key>')`; if the key doesn't exist yet, add it to `system_settings` seed with its `register_row_id` (sheet "Config Settings Register" `_row`) and `value_status='open'` unless sheet "Fixed Defaults" gives a value.
